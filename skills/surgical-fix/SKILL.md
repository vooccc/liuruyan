# 工作模式纪律 · 外科手术档位

线上炸了。下面是**只修问题、不引风险**的极端纪律。

## 心法

**外科医生不会在切阑尾时顺便把胆囊也割了。**

线上 hotfix 不是重构机会，不是优化机会，不是清理 tech debt 机会——
**只解决"现在这个流血点"，其他什么都不动。**

## 1. 改动范围零冗余

- **能改 1 行不改 2 行**：一个 typo 一行能修就一行，不要顺手把整个函数重排
- **不动无关变量**：和 bug 无关的代码碰都不碰
- **不重命名**：哪怕变量名再丑，hotfix 不是改名时机
- **不动格式**：缩进/空行/分号都保持原样，让 diff 干净到能一眼看完

## 2. 修复必须可逆

- 修复方案要满足"如果改完出新问题，5 秒能 revert 回去"
- 优先考虑**加防御代码**而不是**改算法**：
  - 改 `if x` 为 `if x and x.is_valid()` 比重写算法更安全
  - 加 `try/except` 限定 + 降级路径，比改控制流更安全
- 如果 hotfix 必须改算法，**先在本地复现 bug**，确认修后真的好了，再发版

## 3. 根因 vs 现象的取舍

紧急场景下：

- **先止血，后追因**：现象层贴膏药是允许的，但**必须留 TODO 注释**指向根因
  ```python
  # TODO: HOTFIX 2025-XX-XX 临时兜底，根因是 upstream X 在 Y 条件下返回 None
  # 应该在 @path/to/upstream.py:123 修，但今天先这样止血
  if x is None:
      return default
  ```
- **不要在 hotfix 里追根因**：改源头是事后的事，hotfix 必须 atomic、minimal、可验证

## 4. 验证比修复更重要

- 部署前必须有**复现 bug 的最小步骤**——能复现才能验证修复
- 加一条**失败用例**到测试套，覆盖这个具体的 bug
- 验证四件套：
  1. bug 不再出现（正面用例）
  2. 原本正常的路径仍然正常（回归用例）
  3. 边界情况（null/空/超长）
  4. 撤销路径（rollback 后系统能回到稳定态）

## 5. 通讯纪律

- **修完立刻周知**：在团队/老板面前明确说"修了什么、怎么修的、为什么是这样修"
- **诚实说明 trade-off**：如果是临时兜底，不要包装成"完美修复"
- **留追踪票据**：根因修复要进 backlog，不能就这么算了

---

> **底线**：hotfix 完成的标志不是"代码改完了"，是"问题不再发生 + 没引入新问题 + 团队知情"。
> 三个都齐了才算完。
